\begin{abstract}
Code clone \emph{detection}, deciding whether two programs are semantically equivalent despite syntactic differences, has matured into a rich body of work spanning source- and binary-level analysis. The inverse problem, however, remains largely unexplored: given a program, can we \emph{generate} a functional clone that preserves its observable behavior while presenting a materially different implementation? This capability is valuable for software diversification, dependency modernization (e.g., replacing a vulnerable or slow library with a safer or faster one), and the resilience of critical-infrastructure software. In this paper, we present \sys, an agentic system that, given a source program and a set of requirements, synthesizes a working code clone through the coordinated action of a Library-Substitution Agent that swaps third-party dependencies for functionally comparable but more secure or performant alternatives, a Glue-Synthesis Agent that adapts the surrounding program to the new dependency's interface, a Logic-Mutation Agent that rewrites first-party application logic into behaviorally equivalent yet textually divergent code, and a Verification and Consistency Agent that gates every change against a deterministic completeness check and an independent model review, routing each detected regression back to the specific agent responsible for it. A fifth agent stands in for the first two when no comparable third-party library exists to substitute. \sys couples two tiers of verification: a local execute-and-repair loop, in which the agents that rewrite first-party logic check each candidate against recorded golden vectors before it is trusted, and this global acceptance gate, which independently confirms the change is complete and routes any regression back to the agent responsible before it can reach the next stage. We evaluate \sys on twelve programs that estimate factory measurements and control industrial infrastructure, against a single-shot LLM baseline, a single-shot baseline with one evidence-fed repair call added, and an ablation with the verification tier disabled. Conventional measures, compilation and test-suite pass rate, separate the four configurations only weakly, because every subject injects its own dependencies and so never executes the migrated code path under test. Requiring a verified, oracle-confirmed migration instead, full \sys leads decisively: it migrates 32 of 36 runs (88.9\%), against 18 (50.0\%) for the plain single-shot baseline and 20 (55.6\%) with repair added, and against 27 (75.0\%) for the ablation without verification. An independent blind review of all 144 generated clones by a separate, stronger model finds full \sys produces both the most clones rated clean and the fewest rated major-or-broken of any configuration in absolute terms, though at this corpus size that is a directional finding rather than a conclusively established one. The gain in migration success costs roughly seventeen times the dollar cost, and thirty-three times the tokens, of the plain baseline. These results suggest that a verification tier built around a concrete, source-level equivalence oracle, rather than test-suite passage alone, is what turns agentic clone generation from a plausible demonstration into a dependable one.
\end{abstract}
